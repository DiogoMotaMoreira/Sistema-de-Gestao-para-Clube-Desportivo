GUIA DO PROJETO: Sistema de Gestão para Clube Desportivo
1. O QUE TEMOS (A Nossa Arquitetura)
Montámos uma arquitetura moderna, profissional e dividida em três grandes blocos, todos orquestrados pelo Docker. O Docker atua como um "gestor de contentores", garantindo que não instalas "lixo" diretamente no teu computador (Linux) e mantendo tudo super rápido.

Frontend (A "Cara" - Pasta /frontend): Desenvolvido em React Native com a framework Expo. É o que corre no teu iPhone. Responsável pelos botões, ecrãs e por interagir com o utilizador.

Backend (O "Cérebro" - Pasta /backend): Desenvolvido em Java com a framework Spring Boot. É o servidor da tua aplicação. Recebe os pedidos do telemóvel, processa as regras de negócio e decide o que fazer.

Base de Dados (A "Memória" - Contentor MySQL): Um servidor MySQL versão 8 a correr silenciosamente no Docker. Guarda os utilizadores, jogadores, equipas, etc.

2. PORQUÊ ESTA ESCOLHA? (O Raciocínio)
Performance do teu PC: Ao usar o Expo no iPhone, eliminámos os emuladores pesados do Android Studio. O teu computador só precisa de correr texto, deixando a renderização gráfica para o processador do telemóvel.

Separação de Responsabilidades: O telemóvel não acede diretamente à base de dados (o que seria um enorme risco de segurança). O telemóvel fala com o Java, e só o Java tem a password para falar com o MySQL.

Segurança e Escalabilidade: O ecossistema Spring Boot com MySQL é o standard da indústria. Além de criar as tabelas automaticamente por ti (via Hibernate), atua como o "guarda-costas" do clube. No futuro, quando fores implementar as configurações de RLS (Row Level Security) que se encontram de momento desativadas, o Java permite-te programar essas regras de acesso facilmente, garantindo que um treinador só vê os dados da sua própria equipa antes sequer da informação sair do servidor.

3. COMO TRABALHAR NO DIA A DIA (O Teu Fluxo)
Sempre que te sentares no computador para programar, a rotina é sempre a mesma. Vais precisar de dois terminais abertos (um para o servidor Java e outro para o telemóvel).

PASSO 1: Ligar o Motor (No terminal Linux normal)
Na raiz do teu projeto, garante que os contentores estão ligados:

Bash
docker compose up -d
(Se eles já estiverem ligados, o Docker apenas avisa que já estão a correr).

PASSO 2: Arrancar o Servidor Backend (Java)
Abre o Terminal 1, entra no ambiente de desenvolvimento e arranca o Java:

Bash
docker compose exec react-native bash
cd backend
./mvnw spring-boot:run
(O servidor fica a correr na porta 8080. Deixa este terminal aberto).

PASSO 3: Arrancar a App Frontend (Expo)
Abre o Terminal 2, entra no mesmo ambiente, mas vai para a pasta do telemóvel:

Bash
docker compose exec react-native bash
cd frontend
npx expo start --tunnel
(Lê o QR Code com o iPhone para abrir a aplicação. Deixa este terminal aberto).

PASSO 4: Programar!
Abre o teu VS Code no Linux.

Se quiseres mexer nos ecrãs, editas os ficheiros na pasta frontend. O telemóvel atualiza na hora.

Se quiseres criar novas tabelas (ex: Treinador, Equipa) ou criar rotas na API, editas os ficheiros .java na pasta backend/src/main/java/.... Quando guardares, só tens de parar o Terminal 1 (Ctrl + C) e voltar a correr ./mvnw spring-boot:run.

4. COMO DESLIGAR E RESOLVER PROBLEMAS
Para encerrar o dia de trabalho:

Vai a cada terminal e pressiona Ctrl + C para parar o Expo e o Java.

Escreve exit em ambos para saíres do Docker.

Se quiseres poupar memória RAM no teu PC, desliga os contentores com: docker compose down

Resolução de Problemas: O Erro de Permissões (Permission Denied)
Como o Docker atua como Administrador (root) lá dentro, às vezes cria ficheiros de compilação que o teu utilizador Linux não consegue editar ou apagar no VS Code. Se levares com um erro de permissões ou um "cadeado" nos ficheiros, corre isto no teu terminal Linux (na raiz do projeto):

Bash
sudo chown -R $USER:$USER .
Isto devolve-te a propriedade de todos os ficheiros da pasta.
