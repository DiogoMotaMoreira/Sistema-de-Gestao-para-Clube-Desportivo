## Família UC-01: Gestão de Atletas


| Campo | Valor |
|---|---|
| Use Case | UC-01.1: Registar perfil de atleta |
| Use Case | UC-01.1: Registar perfil de atleta |
| Descrição | Criar o cadastro biográfico completo de um novo atleta e associá-lo incondicionalmente à ficha do seu respetivo Encarregado de Educação, centralizando a entidade mestre no diretório do clube. |
| Atores | Secretaria (Primário) |
| Pré-condição | - O ator encontra-se autenticado no sistema com os privilégios operacionais válidos.<br>- A ficha do Encarregado de Educação responsável já se encontra consolidada no sistema (mesmo em casos de maioridade, onde o atleta é o próprio encarregado). |
| Pós-condição (Sucesso) | - O perfil biográfico do atleta encontra-se ativo no diretório central com um identificador único interno gerado.<br>- A associação hierárquica e financeira entre o atleta e o Encarregado de Educação encontra-se consolidada para referência em módulos subsequentes. |
| Fluxo Normal | 1. O ator manifesta a intenção de registar o perfil individual de um novo atleta.<br>2. O sistema valida as permissões de acesso do ator ao escopo de gestão biográfica.<br>3. O sistema requer a submissão da matriz biográfica (nome completo, data de nascimento, fotografia de identificação) e a referência de ligação ao Encarregado de Educação.<br>4. O ator submete os dados biográficos requeridos e a identificação do respetivo Encarregado de Educação.<br>5. O sistema verifica se todas as propriedades obrigatórias da matriz biográfica foram preenchidas.<br>6. O sistema verifica a unicidade dos atributos de identificação no diretório biográfico para garantir que não existem sobreposições cadastrais.<br>7. O sistema valida se a referência do Encarregado de Educação apontada corresponde a um perfil ativo e íntegro na base institucional.<br>8. O sistema gera automaticamente um identificador único interno para o novo atleta.<br>9. O sistema persiste a gravação do perfil, consolida o mapeamento hierárquico familiar e confirma o sucesso da operação ao ator. |
| Fluxos Alternativos | - **Atribuição Complementar de Vínculo Associativo**<br>4a. O ator submete os dados biográficos, a referência do Encarregado de Educação e fornece condicionalmente o Número de Sócio do atleta.<br>4b. O sistema regista o vínculo associativo e anexa a propriedade alfanumérica secundária ao perfil em formação.<br>4c. O fluxo retoma no passo 5. |
| Fluxos de Exceção | - **Interdição de Privilégios de Acesso**<br>2a. O sistema determina que o ator não demonstra a delegação explícita na matriz de privilégios para esta operação.<br>2b. O sistema notifica o ator com uma comunicação padronizada de interdição normativa e bloqueia o pedido.<br>2c. O Caso de Uso encerra.<br>- **Omissão na Matriz Biográfica**<br>5a. O sistema deteta a ausência de parâmetros obrigatórios no conjunto de dados biográficos fornecido.<br>5b. O sistema alerta o ator sobre as métricas em falta e descarta a progressão da gravação.<br>5c. O Caso de Uso encerra.<br>- **Violação de Unicidade de Perfis**<br>6a. O sistema deteta que os identificadores civis introduzidos já pertencem a um perfil existente no diretório central.<br>6b. O sistema notifica o ator da tentativa de duplicação e reverte a operação para garantir a integridade relacional.<br>6c. O Caso de Uso encerra.<br>- **Inconformidade na Associação Hierárquica**<br>7a. O sistema constata que o Encarregado de Educação indicado não existe no ecossistema ou possui um estatuto corrompido.<br>7b. O sistema informa o ator da impossibilidade orgânica de estabelecer a associação incondicional e aborta a criação do perfil.<br>7c. O Caso de Uso encerra. |

| Use Case | UC-01.2: Editar perfil de atleta |
| Use Case | UC-01.2: Editar perfil de atleta |
| Descrição | Atualizar dados cadastrais de um atleta existente no diretório central, garantindo a proteção e o controlo estrito de privilégios sobre a alteração de campos críticos. |
| Atores | Secretaria (Primário), Administrador de Sistema (Secundário) |
| Pré-condição | - O ator encontra-se autenticado no sistema com privilégios mínimos de gestão biográfica.<br>- O perfil do atleta alvo encontra-se previamente registado e ativo no sistema. |
| Pós-condição (Sucesso) | - Os dados biográficos do atleta encontram-se atualizados no diretório central.<br>- O evento de alteração encontra-se registado de forma imutável no histórico de auditoria. |
| Fluxo Normal | 1. O ator manifesta a intenção de editar o perfil de um atleta existente.<br>2. O sistema valida as permissões base de acesso do ator à gestão biográfica.<br>3. O ator seleciona a entidade do atleta pretendido.<br>4. O sistema disponibiliza os dados cadastrais e biográficos atuais do atleta.<br>5. O ator submete o novo conjunto de dados atualizados.<br>6. O sistema verifica a integridade e os formatos dos dados submetidos.<br>7. O sistema avalia se as alterações submetidas incidem sobre campos críticos (nome completo ou data de nascimento).<br>8. O sistema valida se o ator detém privilégios de Administrador de Sistema para autorizar a modificação sensível.<br>9. O sistema persiste as alterações submetidas no diretório central.<br>10. O sistema regista os detalhes da modificação no histórico de auditoria.<br>11. O sistema confirma o sucesso da atualização ao ator. |
| Fluxos Alternativos | - **Edição isenta de campos críticos**<br>7a. O sistema determina que as alterações submetidas não afetam campos biográficos críticos.<br>7b. O fluxo retoma no passo 9. |
| Fluxos de Exceção | - **Interdição de acesso ao módulo**<br>2a. O sistema determina que o ator não possui os privilégios mínimos para a gestão biográfica.<br>2b. O sistema notifica o ator da interdição de acesso e cancela a operação.<br>2c. O Caso de Uso encerra.<br>- **Inconformidade na submissão de dados**<br>6a. O sistema deteta que os dados submetidos omitem parâmetros obrigatórios ou violam as regras de formatação.<br>6b. O sistema alerta o ator sobre a anomalia nos dados e descarta a progressão da gravação.<br>6c. O Caso de Uso encerra.<br>- **Privilégios insuficientes para campos críticos**<br>8a. O sistema determina que o ator não possui o perfil de Administrador de Sistema exigido para alterar o nome ou data de nascimento.<br>8b. O sistema informa o ator sobre a restrição de segurança estrutural e reverte a operação de edição para proteger a integridade dos dados.<br>8c. O Caso de Uso encerra. |

| Use Case | UC-01.3: Arquivar atleta |
| Use Case | UC-01.3: Arquivar atleta |
| Descrição | Desativar o vínculo desportivo ativo de um atleta, preservando o histórico estatístico da época. |
| Atores | Direção Técnica (Primário) |
| Pré-condição | - O ator encontra-se autenticado no sistema com os privilégios operacionais de Direção Técnica.<br>- O perfil do atleta selecionado encontra-se num estado ativo no diretório central. |
| Pós-condição (Sucesso) | - O perfil da entidade transita definitivamente para o estado inativo/arquivado.<br>- O atleta deixa de estar visível e passível de integração em todas as áreas operacionais ativas (listas de presenças, convocatórias e grelhas médicas).<br>- O somatório histórico de atuações, avaliações, assiduidade e infrações do atleta é preservado para efeitos de cálculo analítico global da época.<br>- O portal do Encarregado de Educação fica inibido de realizar novas submissões burocráticas ou clínicas para datas posteriores à eficácia do desvínculo. |
| Fluxo Normal | 1. O ator manifesta a intenção de cessar o vínculo desportivo de um atleta ativo.<br>2. O sistema valida as permissões de acesso do ator para a operação de arquivamento.<br>3. O sistema requer a identificação do atleta, a introdução das metainformações explicativas da cisão e a data de eficácia do desvínculo.<br>4. O ator submete a identificação do atleta alvo, a justificação descritiva e a data de cessação.<br>5. O sistema verifica se os campos obrigatórios relativos à justificação e à data de eficácia foram integralmente preenchidos.<br>6. O sistema valida se o atleta indicado se encontra efetivamente num estado orgânico ativo.<br>7. O sistema altera o domínio da propriedade de estado da entidade para inativo, associando-lhe a metainformação submetida.<br>8. O sistema suspende transversalmente a presença do identificador do atleta nas interfaces operacionais ativas (técnicas e clínicas).<br>9. O sistema bloqueia a capacidade de submissão de novas justificações ou provas médicas no painel do parceiro cliente a partir da data de eficácia.<br>10. O sistema regista a alteração de estado no histórico de auditoria.<br>11. O sistema confirma a conclusão do arquivamento e o sucesso da operação ao ator. |
| Fluxos Alternativos | - **Ausência de Portal de Cliente associado**<br>9a. O sistema determina que o atleta não possui um perfil de portal de cliente (Encarregado de Educação) ativado ou configurado.<br>9b. O sistema ignora a aplicação do bloqueio de submissões externas.<br>9c. O fluxo retoma no passo 10. |
| Fluxos de Exceção | - **Interdição de Privilégios de Acesso**<br>2a. O sistema determina que o ator não demonstra a delegação explícita na matriz de privilégios para executar cessações de vínculo.<br>2b. O sistema notifica o ator da interdição normativa e bloqueia o pedido.<br>2c. O Caso de Uso encerra.<br>- **Omissão de Justificação Formal**<br>5a. O sistema deteta a ausência da metainformação explicativa obrigatória ou da data de eficácia na submissão.<br>5b. O sistema alerta o ator sobre a obrigatoriedade da justificação de desvínculo e descarta a progressão do arquivamento.<br>5c. O Caso de Uso encerra.<br>- **Atleta Inelegível para Arquivamento (Já Inativo)**<br>6a. O sistema deteta que a entidade selecionada já se encontra num estado persistente inativo ou arquivado.<br>6b. O sistema informa o ator de que o atleta não possui um vínculo ativo passível de interrupção e aborta a operação.<br>6c. O Caso de Uso encerra. |

## Família UC-02: Gestão de Encarregados de Educação


| Campo | Valor |
|---|---|
| Use Case | UC-02.1: Registar ficha de Encarregado de Educação |
| Use Case | UC-02.1: Registar ficha de Encarregado de Educação |
| Descrição | Criar o perfil mestre do responsável financeiro e familiar, centralizando os contactos e o estatuto associativo para alimentar os processos de comunicação e faturação. |
| Atores | Secretaria (Primário) |
| Pré-condição | - O ator encontra-se autenticado no sistema com privilégios operacionais de gestão administrativa. |
| Pós-condição (Sucesso) | - A ficha mestre do Encarregado de Educação encontra-se criada e consolidada no diretório central.<br>- O vínculo associativo (estatuto de Sócio) encontra-se registado e disponível como parâmetro de decisão para o motor de provisão financeira. |
| Fluxo Normal | 1. O ator manifesta a intenção de registar um novo Encarregado de Educação.<br>2. O sistema valida as permissões de acesso do ator para a criação de registos mestres.<br>3. O sistema requer a metainformação residencial, os dados de contacto, a identificação civil (NIF/ID) e o estado do vínculo associativo.<br>4. O ator submete a informação requerida do responsável.<br>5. O sistema verifica se todos os campos obrigatórios da metainformação foram preenchidos.<br>6. O sistema verifica a unicidade da identificação civil (NIF/ID) para garantir a inexistência de duplicação no diretório biográfico.<br>7. O sistema persiste a nova ficha do Encarregado de Educação e o seu estatuto associativo.<br>8. O sistema regista a operação de criação no histórico de auditoria.<br>9. O sistema confirma a consolidação do perfil ao ator. |
| Fluxos Alternativos | - **Registo de atleta emancipado ou maior de idade**<br>4a. O ator submete os dados de identificação civil e contacto do próprio atleta, assumindo-o na função de Encarregado de Educação.<br>4b. O sistema atribui a identidade submetida como titular da responsabilidade financeira mestre.<br>4c. O fluxo retoma no passo 5. |
| Fluxos de Exceção | - **Interdição de Privilégios de Acesso**<br>2a. O sistema determina que o ator não demonstra privilégios autorizados para manipular o diretório de Encarregados de Educação.<br>2b. O sistema notifica o ator com uma comunicação de interdição de acesso e aborta o pedido.<br>2c. O Caso de Uso encerra.<br>- **Omissão de Dados Obrigatórios**<br>5a. O sistema deteta a ausência de parâmetros exigidos na metainformação submetida (ex: NIF ou morada em falta).<br>5b. O sistema alerta o ator sobre os dados omitidos e descarta a progressão da gravação.<br>5c. O Caso de Uso encerra.<br>- **Violação de Unicidade de Identificador (NIF/ID)**<br>6a. O sistema deteta que a identificação civil submetida já se encontra associada a um perfil de Encarregado de Educação pré-existente.<br>6b. O sistema alerta o ator para a tentativa de duplicação de identidade e reverte a operação para proteger a integridade do diretório biográfico.<br>6c. O Caso de Uso encerra. |

| Use Case | UC-02.2: Editar ficha de Encarregado de Educação |
| Descrição | Atualizar dados de contacto, residência e estatuto de sócio do responsável financeiro e familiar no diretório central, refletindo o impacto cadastral nas obrigações pendentes. |

| Fluxo Normal | 1. O ator manifesta a intenção de editar a ficha de um Encarregado de Educação.<br>2. O sistema valida as permissões de acesso do ator à gestão de perfis familiares mestres.<br>3. O ator seleciona o perfil do Encarregado de Educação pretendido.<br>4. O sistema disponibiliza os dados cadastrais, residenciais e associativos atuais do responsável.<br>5. O sistema valida se ocorreram modificações na morada fiscal ou no estatuto de sócio.<br>8. O sistema atualiza os parâmetros associados e aplica a nova configuração às obrigações financeiras pendentes (quotas e mensalidades).<br>9. O sistema persiste as alterações no perfil central.<br>10. O sistema regista os detalhes da operação no histórico de auditoria.<br>11. O sistema confirma a atualização com sucesso ao ator. |
| Fluxos Alternativos | - **Modificação do Vínculo Associativo (Estatuto de Sócio)**<br>7a. O sistema deteta que a alteração submetida modifica o estatuto de Sócio do Encarregado de Educação.<br>7b. O sistema processa o envio de uma notificação automática informando o titular sobre a alteração do estatuto e o respetivo impacto nos benefícios.<br>7c. O fluxo retoma no passo 8.<br>- **Atualização Estrita de Meios de Contacto**<br>7a. O sistema determina que as alterações submetidas incidem exclusivamente sobre meios de contacto direto (telemóvel ou email), sem afetar a morada fiscal ou o estatuto associativo.<br>7b. O fluxo retoma no passo 9. |
| Fluxos de Exceção | - **Interdição de Privilégios de Acesso**<br>2a. O sistema determina que o ator não demonstra delegação explícita para modificar dados mestres do diretório familiar.<br>2b. O sistema notifica o ator da interdição de segurança e bloqueia a operação.<br>2c. O Caso de Uso encerra.<br>- **Inconformidade na Submissão de Dados**<br>6a. O sistema deteta a omissão de campos obrigatórios ou a presença de formatos inválidos nos dados submetidos.<br>6b. O sistema alerta o ator para a anomalia cadastral e descarta a progressão da gravação.<br>6c. O Caso de Uso encerra. |

O sistema notifica o ator da interdição de acesso e descarta a operação.<br>2c. O Caso de Uso encerra.<br>- **Perfil de Atleta Inexistente ou Arquivado**<br>4a. O sistema deteta que a identificação submetida não corresponde a um registo de atleta válido ou encontra-se em estado arquivado.<br>4b. O sistema alerta o ator para a anomalia na entidade desportiva e aborta o pedido.<br>4c. O Caso de Uso encerra.<br>- **Ficha de Encarregado de Educação Inativa ou Inválida**<br>5a. O sistema constata que a ficha do Encarregado de Educação indicada se encontra num estado inativo ou apresenta inconformidades cadastrais.<br>5b. O sistema informa o ator da impossibilidade orgânica de estabelecer a tutela financeira e cancela a operação.<br>5c. O Caso de Uso encerra. |
